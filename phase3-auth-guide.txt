========================================
PHASE 3 — AUTH DISCORD OAUTH2 + JWT + GUARDS
Guide détaillé étape par étape
========================================

Objectif : verrouiller l'API. Sans ça, n'importe qui peut appeler les
routes. Toutes les routes de la Phase 4 (guilds, members, logs...)
dépendront des guards construits ici.

Etat actuel (voir api-roadmap-journal.txt) :
- modules/auth/ existe avec 3 fichiers, mais auth.controller.ts et
  auth.service.ts sont VIDES, auth.module.ts n'est qu'un squelette,
  et AuthModule n'est pas enregistré dans app.module.ts.
- Rien n'est fonctionnel côté auth pour l'instant : tout est à écrire.


----------------------------------------
PREREQUIS — Discord Developer Portal
----------------------------------------

Sur https://discord.com/developers/applications, dans l'appli du bot :
- Onglet OAuth2 -> ajouter une Redirect URI :
  http://localhost:3000/auth/discord/callback
- Récupérer Client ID et Client Secret, les mettre dans .env :
  DISCORD_CLIENT_ID=...
  DISCORD_CLIENT_SECRET=...
- Générer un vrai JWT_SECRET (pas "change_me") avant de tester en réel :
  openssl rand -hex 32


----------------------------------------
ETAPE 1 — Middleware cookie-parser + CORS (main.ts)
----------------------------------------

cookie-parser est déjà en dépendance mais pas branché. Nécessaire pour
lire req.cookies dans les guards.

  import cookieParser from 'cookie-parser';
  app.use(cookieParser());
  app.enableCors({ origin: process.env.DASHBOARD_URL, credentials: true });

Le credentials: true est indispensable : sans ça, le navigateur du
dashboard (origine différente) n'enverra jamais le cookie JWT à l'API.


----------------------------------------
ETAPE 2 — auth.module.ts
----------------------------------------

Configurer JwtModule avec le secret depuis .env (actuellement importé
mais pas configuré) :

  JwtModule.registerAsync({
    inject: [ConfigService],
    useFactory: (config: ConfigService) => ({
      secret: config.get<string>('JWT_SECRET'),
      signOptions: { expiresIn: '7d' },
    }),
  }),

Déclarer AuthController et AuthService dans le module. Exporter
JwtModule si les guards d'autres modules doivent injecter JwtService.

Ne pas oublier : enregistrer AuthModule dans les imports de
app.module.ts (actuellement absent).


----------------------------------------
ETAPE 3 — La logique OAuth2 dans auth.service.ts
----------------------------------------

Le flow Authorization Code de Discord = 4 appels HTTP.

1) Construire l'URL d'autorisation (utilisée par la route /auth/discord) :

  https://discord.com/api/oauth2/authorize
    ?client_id=DISCORD_CLIENT_ID
    &redirect_uri=http://localhost:3000/auth/discord/callback
    &response_type=code
    &scope=identify guilds

  Le scope "guilds" est indispensable pour ensuite savoir sur quels
  serveurs l'utilisateur a la permission MANAGE_GUILD.

2) Echanger le code contre un access_token (dans le callback) :
   POST https://discord.com/api/oauth2/token
   en application/x-www-form-urlencoded avec :
   grant_type=authorization_code, code, redirect_uri, client_id,
   client_secret.

3) Récupérer l'identité :
   GET https://discord.com/api/users/@me
   avec Authorization: Bearer <access_token>
   -> renvoie id, username, avatar.

4) Récupérer les guilds et filtrer par permission :
   GET https://discord.com/api/users/@me/guilds
   avec le même token -> renvoie une liste d'objets { id, name,
   permissions, ... }. "permissions" est une string représentant un
   bitfield. La permission MANAGE_GUILD correspond au bit 0x20 :

     const MANAGE_GUILD = 0x20n;
     const hasAccess = (BigInt(guild.permissions) & MANAGE_GUILD) === MANAGE_GUILD;

   Filtrer la liste pour ne garder que les guilds où c'est vrai -> cette
   liste d'ids va dans le payload du JWT.

5) Signer le JWT :

     jwtService.sign({ sub: discordUser.id, username, guilds: [idsFiltrés] })


----------------------------------------
ETAPE 4 — auth.controller.ts, les 4 routes
----------------------------------------

- GET /auth/discord
  -> res.redirect(urlDiscord) (construite à l'étape 3.1)

- GET /auth/discord/callback?code=...
  -> appelle le service (étapes 3.2 à 3.5), puis :
     res.cookie('token', jwt, {
       httpOnly: true,
       sameSite: 'lax',
       secure: false, // true en prod
     })
     res.redirect(DASHBOARD_URL)

- POST /auth/logout
  -> res.clearCookie('token')

- GET /auth/me
  -> protégée par JwtGuard, retourne req.user (injecté par le guard)

Attention : pour utiliser res.cookie / res.redirect directement, ces
handlers doivent utiliser @Res({ passthrough: true }) — sinon Nest perd
la main sur la réponse et le ValidationPipe/interceptors ne s'appliquent
plus.


----------------------------------------
ETAPE 5 — guards/jwt.guard.ts
----------------------------------------

Un CanActivate qui :
1. lit request.cookies['token']
2. si absent -> throw new UnauthorizedException()
3. jwtService.verify(token) (catch l'erreur si expiré/invalide ->
   UnauthorizedException)
4. attache le payload décodé à request.user
5. return true


----------------------------------------
ETAPE 6 — guards/guild.guard.ts
----------------------------------------

Un second CanActivate, appliqué APRES le JwtGuard (Nest exécute les
guards dans l'ordre du tableau @UseGuards(JwtGuard, GuildGuard)) :
1. lit request.params.guildId
2. vérifie que request.user.guilds.includes(guildId)
3. sinon -> throw new ForbiddenException()


----------------------------------------
ETAPE 7 — Appliquer les guards
----------------------------------------

Sur chaque contrôleur de la Phase 4 (guilds, members, logs...) :

  @UseGuards(JwtGuard, GuildGuard)

au niveau classe, sur les routes qui contiennent :guildId.


----------------------------------------
POINTS DE VIGILANCE
----------------------------------------

- JWT_SECRET=change_me dans .env -> à remplacer par un vrai secret
  aléatoire avant de tester (un JWT signé avec "change_me" est
  trivialement forgeable).
- CORS + credentials: true (étape 1) doivent être en place AVANT de
  tester le callback depuis le dashboard, sinon le cookie ne partira
  jamais du navigateur vers l'API.
- Penser à enregistrer AuthModule dans app.module.ts une fois les
  fichiers remplis (actuellement absent).
